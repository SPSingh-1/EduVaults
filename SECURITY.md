# Security Policy

Thank you for helping keep **EduVaults** secure.

The security of our platform and the privacy of our users are our highest priorities. We appreciate responsible disclosure of security vulnerabilities and will work with security researchers and users to investigate and resolve legitimate issues as quickly as possible.

---

# Supported Versions

Only the latest stable release of EduVaults receives security updates.

| Version | Supported |
|----------|-----------|
| Latest Stable Release | ✅ Yes |
| Older Releases | ❌ No |

We strongly recommend upgrading to the latest version to receive the newest security patches and improvements.

---

# Reporting a Vulnerability

If you believe you have discovered a security vulnerability in EduVaults, please report it privately.

**Email:** spsrajjput@gmail.com

Please **do not** create a public GitHub issue for security vulnerabilities.

### Include the following information:

- Description of the vulnerability
- Steps to reproduce the issue
- Affected version
- Potential impact
- Screenshots or Proof of Concept (if available)
- Suggested fix (optional)

Providing as much detail as possible helps us investigate the issue more quickly.

---

# Response Timeline

Our goal is to respond according to the following timeline:

| Action | Expected Time |
|---------|---------------|
| Initial acknowledgement | Within 48 hours |
| Initial assessment | Within 5 business days |
| Status updates | Every 7 days |
| Security fix | As soon as possible based on severity |

Complex issues may require additional investigation time.

---

# Responsible Disclosure Guidelines

We ask that you:

- Report vulnerabilities privately.
- Allow us reasonable time to investigate and release a fix.
- Avoid publicly disclosing vulnerabilities before they are resolved.
- Act in good faith to protect our users.

Please do **NOT**:

- Access, modify, or delete data that does not belong to you.
- Attempt denial-of-service (DoS/DDoS) attacks.
- Perform social engineering attacks.
- Use automated attacks that may impact service availability.
- Exploit vulnerabilities beyond what is necessary to demonstrate the issue.

---

# Scope

This policy applies to the following EduVaults components:

- Web Application
- REST APIs
- Authentication & Authorization
- School Management Portal
- Student Portal
- Teacher Portal
- Admin Dashboard
- Multi-Tenant Infrastructure
- Database Layer
- File Upload System
- Notifications
- User Management

Third-party services and integrations are governed by their own security policies.

---

# Security Best Practices

To maintain a secure EduVaults deployment, we recommend:

- Always use HTTPS.
- Keep EduVaults updated to the latest version.
- Use strong, unique passwords.
- Enable Multi-Factor Authentication (when available).
- Restrict database access to trusted networks.
- Rotate API keys and secrets regularly.
- Apply the principle of least privilege.
- Keep operating systems and dependencies updated.
- Perform regular backups.
- Monitor authentication logs for suspicious activity.

- Users may be advised to update immediately.
- Public disclosure may occur after remediation to help users understand the issue.
